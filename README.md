# ukr-geo-gitcall

Код для виклику через **Corezoid Git Call** вузол: визначає, у якій
адмінодиниці 2-го рівня (районі) України знаходиться точка за
координатами `lat`/`lon`.

Формат репозиторію відповідає офіційним прикладам Corezoid
([corezoid/gitcall-examples](https://github.com/corezoid/gitcall-examples)):
`usercode.js` в корені експортує одну функцію, яка приймає параметри
задачі (`data`) і повертає їх (доповненими) або кидає помилку.

## Структура репозиторію

```
ukr-geo-gitcall/
├── usercode.js                    # точка входу для Git Call вузла
├── geoIndex.js                    # завантаження geojson + пошук точки в полігоні
├── package.json                   # npm-залежності (@turf/*)
└── data/
    └── ukr_admin2_light.geojson   # вхідні дані з полігонами районів
```

## Заливка великого geojson-файлу (26+ МБ) на GitHub

Якщо файл не проходить обмеження GitHub — важливо розрізняти два
різних ліміти, які часто плутають:

- **25 МБ** — ліміт лише **веб-інтерфейсу** GitHub (перетягування
  файлу мишкою в браузері через "Add file → Upload files").
- **100 МБ** — реальний жорсткий ліміт для одного файлу через звичайний
  `git push` з командного рядка (git видасть попередження вже з 50 МБ,
  але сам push пройде успішно).

Файл 26,3 МБ спокійно влазить у другий ліміт. Тобто рішення —
заливати репозиторій через git CLI, а не через веб-завантаження:

```bash
cd ukr-geo-gitcall
git init
git add .
git commit -m "Initial commit: ukr-geo-gitcall"
git branch -M main
git remote add origin https://github.com/<ваш_акаунт>/<назва_репо>.git
git push -u origin main
```

### Якщо push все одно не проходить

1. **Помилка на кшталт `RPC failed; HTTP 408/413` або обрив з'єднання
   під час push** — типово означає, що локальний git-клієнт або проксі
   обмежує розмір HTTP-запиту. Збільште буфер:
   ```bash
   git config http.postBuffer 524288000
   ```
   (524288000 байт = 500 МБ) і повторіть `git push`.

2. **Push через HTTPS постійно обривається** (нестабільне з'єднання,
   корпоративний проксі тощо) — спробуйте SSH-адресу репозиторію
   замість HTTPS:
   ```bash
   git remote set-url origin git@github.com:<ваш_акаунт>/<назва_репо>.git
   git push -u origin main
   ```

3. **Файл справді перевищує 100 МБ** (наприклад, після додавання
   набагато більшої кількості полігонів) — тоді знадобиться
   [Git LFS](https://git-lfs.com/). Важливий нюанс саме для Git Call:
   немає гарантії, що середовище, у якому Corezoid клонує репозиторій
   для білда вузла, має встановлений `git-lfs`. Якщо його немає —
   замість реального geojson-файлу вузол отримає лише текстовий
   LFS-покажчик (кілька сотень байт), і `JSON.parse` впаде під час
   виконання. Тому LFS варто використовувати тільки якщо ви
   попередньо перевірили (наприклад, тестовим Build у вузлі), що
   реальний вміст файлу підтягується коректно, а не 25-МБ ліміт як
   такий не є для цього причиною.

У переважній більшості випадків достатньо просто пуштити через
термінал (варіант вище) — і жодних додаткових кроків не потрібно.

## Як це працює

- `usercode.js` при старті контейнера (один раз) завантажує geojson у
  пам'ять і потім на кожну задачу лише шукає полігон, що містить точку.
- Вхід: параметри задачі мають містити `lat` і `lon` (числа або рядки
  з числами; підтримуються також синоніми `latitude`/`longitude`/`lng`).
- Вихід (успіх): до параметрів задачі додаються `adm2_name1` та
  `adm2_pcode`, задача йде звичайним потоком далі по процесу.
- Вихід (помилка): якщо параметри некоректні або полігон не знайдено —
  функція кидає `Error`. Задача автоматично йде у службовий
  (error) вихід вузла Git Call, опис помилки буде у параметрі
  `__conveyor_git_call_return_type_description__`. Звичайний вихід у
  цьому випадку жодних нових даних не отримує (тобто результат —
  порожній).

## 1. Перенесення в GitHub

```bash
cd ukr-geo-gitcall
git init
git add .
git commit -m "Initial commit: ukr-geo-gitcall"
git branch -M main
git remote add origin https://github.com/<ваш_акаунт>/<назва_репо>.git
git push -u origin main
```

Якщо репозиторій приватний — або додайте SSH-ключ (див. нижче), або
використовуйте формат URL з логіном/паролем/токеном
`https://<login>:<token>@github.com/<акаунт>/<репо>.git` (менш безпечний
варіант, підходить тільки для тестів).

## 2. Налаштування вузла Git Call у Corezoid

1. У процесі додайте вузол **Git Call**.
2. **Language**: `JavaScript`.
3. **Repo URL**: `https://github.com/<ваш_акаунт>/<назва_репо>.git`
   (або SSH-варіант — натисніть **Get SSH key**, скопіюйте ключ і
   додайте його як Deploy key у налаштуваннях репозиторію на GitHub,
   якщо репозиторій приватний).
4. **Tag / Branch / Commit**: `main`.
5. **Code** (поле редактора коду в самому вузлі): залиште порожнім —
   код уже є в репозиторії як `usercode.js`. Якщо щось введете в цьому
   полі, воно перезапише вміст `usercode.js` з репозиторію під час
   білда — тож для цього проєкту поле краще не чіпати.
6. **Build command**: `npm install` (встановлює залежності
   `@turf/boolean-point-in-polygon` та `@turf/helpers` з `package.json`).
7. Натисніть **Build**, дочекайтесь завершення у терміналі вузла,
   потім **Deploy** процес.

Після першого проходження задачі вузол "прогріється" (10–15 секунд),
далі задачі обробляються миттєво. Якщо вузол простоює понад 10 хв —
знову йде в холодний старт (нормальна поведінка Git Call).

## 3. Приклад задачі

Вхідна задача:

```json
{ "lat": 48.1685, "lon": 24.1819 }
```

Задача на виході зі звичайного потоку вузла (успіх):

```json
{
  "lat": 48.1685,
  "lon": 24.1819,
  "adm2_name1": "Рахівський",
  "adm2_pcode": "UA2106"
}
```

Якщо точку не знайдено (наприклад, координати Києва) — задача піде у
службовий вихід помилки вузла з описом
`"Полігон, що містить задану точку, не знайдено"` у параметрі
`__conveyor_git_call_return_type_description__`. Аналогічно для
некоректних/відсутніх `lat`/`lon`.

## 4. Локальне тестування без Corezoid

```bash
npm install
node -e "
const handle = require('./usercode.js');
console.log(handle({ lat: 48.1685, lon: 24.1819 }));
"
```

## Примітки

- Файл `ukr_admin2_light.geojson`, наданий як приклад, містить лише
  один полігон (Рахівський район). Замініть цей файл повним набором
  районів (усі geometry types Polygon/MultiPolygon коректно
  обробляються) — код без змін працюватиме з будь-якою кількістю
  полігонів.
- `geoIndex.js` попутно вміє читати й `.geojson.gz` (автоматично за
  розширенням файлу), якщо колись захочете стиснути дані — просто
  покладіть `.gz`-файл у `data/` і вкажіть його шлях. Але для
  звичайного нестисненого файлу до 100 МБ це не потрібно.
- Якщо GitHub-репозиторій приватний і ви не хочете використовувати SSH
  Deploy key, врахуйте, що передача логіна/пароля/токена прямо в URL —
  менш безпечний спосіб; SSH-ключ є рекомендованим варіантом Corezoid.
